残課題の調査結果

調査結果：ビルドの原因を特定、ブラウザテストは12件成功・2件失敗

2026年10月19日に調査。アプリの実装・依存関係・システムのNode.jsは変更していません。比較用のNode.jsとテストデータはGit管理外の .tools/ に配置しました。

1. 残件と優先度

優先度項目調査結果次の対応
高ビルド異常終了Node.js 24.11.1の非ASCIIパスに対するfs.rmSyncの不具合。24.13.1で削除テスト・通常ビルド2回が成功。修正を含むNode.js 24系へ更新し、実行環境のPATHと必要バージョンを揃える。
中ブラウザテスト2件失敗PC・モバイル各1件。/private/... の403期待に対しSPAのHTMLが200で返る。実ファイルの@fsアクセスは403。保護対象URLの応答方針を決め、実ファイルの配信拒否を確認するテストと期待値を整える。
中HTML資料の再生成Markdownは01.doc/assetsにあるが、build-docs.pyが01.doc直下から読むためFileNotFoundError。原稿の参照先とHTML出力先を分ける。参照先をassetsへ合わせて再生成を検証する。
中調査用Viteの終了待ち全テストの実行後と、単独のserver.close()で終了待ちを観測。専用プロセスを停止して結果を回収。Viteの監視・接続・API終了処理を個別に追跡する。原因は未確定。
準備待ち実Google認証必要な3変数が現在の実行環境にない。値そのものは読み出さず、設定の有無だけ確認。OAuthクライアント・リダイレクトURI・テストユーザーを準備して実アカウント検証。
準備待ち実画像変換・ウイルス検査scanner・office・rasterがすべてunavailable。現在のPATH・環境設定では利用不可。ClamAVと定義、LibreOffice、Popplerを準備する。
任意独自検知語個人名・会社名はユーザー固有の設定であり、未設定はアプリの不具合ではない。必要時にローカルのkeywords.yamlへ設定。共有しない。

2. ビルドの原因と比較試験

実行環境はWindows、日本語を含むプロジェクトパス、Node.js 24.11.1、Vite 7.3.6。通常ビルドは型検査・32モジュールの変換後、終了コード -1073740791 / 0xC0000409 で停止しました。

  1. 新しい出力先へのビルドは成功。
  2. 同じ出力先に再ビルドし、既存内容の削除が発生すると失敗。
  3. 最小のHTML＋JavaScriptだけの構成でも、2回目のビルドで再現。
  4. emptyOutDir:false にすると既存distへのビルドが成功。
  5. ViteのemptyDirが使う fs.rmSync() を、専用の生成ファイル・ディレクトリで単独実行して同じ終了コードを再現。
  6. Node.js 24.13.1へ実行時のPATHを切り替えると、単独削除と通常の npm run build が2回連続で成功。SEOファイルも6商品分生成。

これにより、Reactの実装・圧縮・Rollupのバイナリ自体を原因とする仮説よりも、古いNode.jsの削除処理が原因と判断できます。構成整理直後に成功していたことも、新規の出力先では削除が発生しない条件と整合します。

Node.js 24.13.1の公式リリースには非ASCII文字のrmSync修正が掲載されています。公式Issue #58759にも同じ終了コードの報告があります。

比較用ランタイムは公式ZIPを取得し、公式SHASUMS256.txtとSHA-256を照合しました。システムのNode.jsは24.11.1のままなので、通常のシェルでのビルド失敗は環境更新まで残ります。初回の比較でnpm.cmdだけを直接指定しても、子コマンドが元のNode.jsを使うことを確認しました。PATHも切り替える必要があります。

# この調査環境に配置した比較用Node.jsで実行する例（PowerShell）
$env:PATH = (Join-Path $PWD '.tools/node-runtime/node-v24.13.1-win-x64') + ';' + $env:PATH
node --version
npm run build

恒久対策は修正済みのNode.js 24系を利用することです。削除を無効にする回避策は古い成果物を残すため、恒久設定としては採用しません。比較用24.13.1は修正確認用であり、最新バージョンの指定ではありません。

3. ブラウザテストとファイル配信の確認

Node.js 24.13.1と既存のMicrosoft Edgeで、PC・モバイル計14件を実行。結果は12件成功・2件失敗です。普段のDB・固定ファイル版に影響しないよう、DB・配布ファイル・バックアップをすべて専用領域へ切り替えました。

要求先実際の応答確認内容
/private/downloads/proposal.pptx200 / text/htmlReact用HTML。ZIP／PPTXでもSQLiteでもない。
/@fs/実ファイルの絶対パス（PPTX）403配信拒否。
/@fs/実ファイルの絶対パス（DB）403配信拒否。
/@fs/実ファイルの絶対パス（server/shop.mjs）403配信拒否。

失敗箇所は 02.src/tests/api.spec.ts:20 のステータス検証です。Viteのルートを02.srcへ変更したため、/private/...は実ファイルの場所と対応せず、SPAフォールバックへ到達します。この試験では非公開ファイルの流出は確認されませんでした。失敗した2ケースは途中で止まるため、その後のアサーションは今回実行できていません。

実ファイルを指定した拒否検証を加え、/private/...自体を403にするか、HTMLフォールバックを許容するかを決めるのが対応案です。403だけを200へ置き換えて済ませると、配信保護の検証が弱くなります。

通常のPlaywright設定にはWindowsで扱いづらい /tmp/... のDB保存先と、固定ファイル版の既存保存先を使う設定が残っています。次の修正時は os.tmpdir() を使い、DBと配布ファイルの両方をテスト専用にするのが適切です。

14ケースの終了後、Viteの終了待ちが継続しました。単独ルート検査の server.close() でも観測したため、原因を特定せず別の残件としています。今回起動した専用Vite・npmプロセスのみ停止し、最終結果を回収しました。3分という実行時間には終了待ちと回収待ちが含まれ、画面操作の性能測定ではありません。

4. 資料の再生成で見つかった問題

python 02.src/scripts/build-docs.py は最初の 01.doc/local-basic-design.md 読み込みで失敗します。実際の原稿は 01.doc/assets/local-basic-design.md です。ほかのMarkdown原稿も同じassets配下にあります。

スクリプトの読み込み先をassetsへ合わせ、出力は01.docに維持する修正が必要です。既存HTMLの閲覧は可能です。再生成試験は最初の原稿読み込みで停止しており、HTMLは変更していません。残課題ファイルにあったimplementation-status.mdへの参照も、現在のHTMLへ直しました。

5. 外部設定・未実装事項

  • Google設定：GOOGLE_CLIENT_ID、GOOGLE_CLIENT_SECRET、GOOGLE_REDIRECT_URIの3変数が未設定。実Google認証の不具合は、この状態では確認できません。
  • 実ツール：npm run tools:checkはscanner・office・rasterをすべてunavailableと報告。現在の実行環境での未導入またはパス未設定であり、画像変換やClamAVそのものの動作不良とは判定していません。
  • 独自検知語：個人名・会社名などは運用者が必要な場合だけ指定する設定です。
  • 実販売：実決済・Webhook・外部メール・本番DB／ストレージ／監視などは既存資料に記載された未実装機能です。今回の調査でこれらを実装済みとは扱っていません。

6. 推奨する対応順

  1. Node.jsの実行環境を更新し、必要な最低版をREADME・package.json等へ明示する。
  2. 配信拒否の仕様とAPIテストの期待値を整え、停止したケースも最後まで再実行する。
  3. 資料原稿の参照先を修正し、再生成・リンク・表示を確認する。
  4. Vite終了待ちとテスト用ファイル保存先の隔離を修正・検証する。
  5. 必要な場合に外部ツールとGoogle設定を準備して実環境検証する。

本調査では原因確認と結果の記録まで実施しました。アプリ実装・依存関係・テスト本体の修正、システムNode.jsの更新、コミット・pushは行っていません。
