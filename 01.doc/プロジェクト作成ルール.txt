# プロジェクト作成ルール

この文書は、新しいプロジェクトを作成するときの初期フォルダ構成と、その後の開発・ドキュメント作成ルールを定めます。

## 1. 最初に作成するフォルダ・ファイル

プロジェクト作成時は、技術スタックを決めたうえで、まず次の基本構成を作成します。言語やフレームワーク固有のファイルは、該当するものだけを追加します。

```text
project-root/
├── 00.secret/                   # ローカル専用の秘密情報置き場。Gitには登録しない
├── 01.doc/                      # 要件定義書・設計書・テスト仕様書など
├── 02.src/                      # アプリケーションのソースコード
├── 03.log/                      # 開発プロンプト・進捗・残課題
│   ├── prompts.txt              # プロジェクトで使うプロンプト
│   ├── current_status.txt       # 現在の進捗・作業状況
│   └── leftover_tasks.txt       # 未完了タスク・残課題
├── .gitignore                   # 00.secretや環境変数ファイルを除外する
├── README.md                    # プロジェクト概要・利用方法
└── （言語・ツールの設定ファイル） # package.json、pyproject.toml等
```

フォルダ名の先頭の番号は、役割ごとの並び順を揃えるために付けます。新しい用途のフォルダを追加する場合も、既存番号と役割を確認し、番号が重複しないようにします。

### 各フォルダ・ファイルの役割

- `00.secret/`: ローカル開発で必要な秘密情報を置く場合の専用領域。フォルダ全体を`.gitignore`で除外し、中のファイルは一切コミットしない。Gitでは空フォルダを管理できないため、必要なときにローカルで作成する。可能なら秘密情報は環境変数や各環境のSecret Managerで管理する。
- `01.doc/`: 要件定義書、基本設計書、詳細設計書、DB設計書、テスト仕様書など、プロジェクトの設計・仕様資料を置く。
- `02.src/`: アプリケーションの実装コードを置く。フレームワークの規約がある場合は、その規約に従ってサブフォルダを構成する。
- `03.log/`: 開発時のプロンプト、進捗、未完了事項を記録するファイルを置く。
- `03.log/prompts.txt`: プロジェクトで再利用するプロンプトを記載する。プロンプトごとに用途を見出しで分け、実際の秘密情報や環境固有の値は含めない。
- `03.log/current_status.txt`: 現在の作業状況、完了した内容、進行中の内容、ブロッカーを記録する。作業状況が変わったときに更新する。
- `03.log/leftover_tasks.txt`: 未完了タスク、残課題、未検証事項を記録する。完了した項目は未完了として残さず、必要に応じて完了状況を更新する。
- `.gitignore`: `00.secret/`の全ファイル、`.env`などの環境変数ファイル、依存関係・ビルド生成物を除外する。`.env.example`など秘密値を含まないテンプレートは、必要に応じて共有する。
- `README.md`: 初めて利用・開発する人がプロジェクトを理解し、セットアップできる入口として作成する。

フレームワークが標準の配置を要求する場合（例: `app/`、`pages/`など）は、無理に構成を崩さず、`02.src/`配下にその規約に沿って配置します。

### GitSecurityToolの取得・組み込み

基本フォルダと基本ファイル（README、`.gitignore`、`03.log/`配下の3ファイル、言語・ツールの設定ファイルなど）を作成した後に、GitSecurityToolを取得して組み込みます。Gitリポジトリを初期化してから、次のコマンドでサブモジュールとして追加します。

```bash
git init
git submodule add https://github.com/tamina0624-study/GitSecurityTool.git GitSecurityTool
```

続けて、プロジェクトルートにGitSecurityTool用の `.pre-commit-config.yaml` を用意し、Python 3.11以上の環境でpre-commitをインストールしてフックを設定します。

```bash
python -m pip install pre-commit
python -m pre_commit install
```

サブモジュールを含めてcloneする場合は `git clone --recurse-submodules <repository-url>` を使います。clone済みのリポジトリでは次のコマンドで取得します。

```bash
git submodule update --init --recursive
```

個人名・会社名などの検知語を設定する場合は、GitSecurityToolの `keywords.yaml` をローカルで作成・編集し、サブモジュール内の `.git/info/exclude` に登録してコミット対象から除外します。独自の秘密情報や検知ログをリポジトリへ登録しないでください。

初期作成時は、上記の基本フォルダと基本ファイルを準備し、GitSecurityToolを組み込んでから実装に進みます。`00.secret/`はGit管理外のため、必要に応じて各開発環境で作成します。
