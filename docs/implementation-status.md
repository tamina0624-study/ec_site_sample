## Googleログインを有効にする作業

1. Google Cloudでウェブアプリ用OAuthクライアントを作成し、OAuth同意画面とテストユーザーを設定する。
2. 実行環境へ `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET`、`GOOGLE_REDIRECT_URI` を設定する。ローカルのリダイレクト先は `http://localhost:5173/api/auth/google/callback`。
3. 開発サーバーを再起動し、実際のGoogleアカウントでログイン、キャンセル、失敗、ログアウト、端末を変えた履歴とダウンロードを確認する。
4. 本番利用時はHTTPSの公開URLをGoogle Cloudへ登録し、`SHOP_COOKIE_SECURE=true` を設定する。Client SecretはSecret管理へ置き、Gitやクライアント側へ出さない。

この環境ではClient ID／Secretが未設定のため、実Googleとの認可コード交換・Google Cloud側の同意画面設定は未検証です。サーバーテストはOIDC部分をモック化して状態遷移と所有権を検証しています。

## 実販売前に残る作業

- 実決済：ホスト型Checkout、署名付きWebhookとイベント重複排除、入金照合、状態不明時の再照会、返金・異議申し立て処理。
- 購入者データ：アカウント削除・データ保持期間・問い合わせ窓口を決定し、プライバシー表示と運用手順へ反映する。
- メールと運用：購入完了・問い合わせ通知の外部配信、再送監視、障害監視、対応手順を整える。
- 本番基盤：SQLiteから本番DBへ移行し、非公開オブジェクトストレージ、HTTPS、Secret管理、検証／本番分離を用意する。
- 販売条件：販売者情報、税区分・税計算、領収書要件、返金条件、提供期間を確定し、実販売用ページと注文記録へ反映する。
- ファイル運用：ClamAV定義の更新手順を確立し、PPTX変換をOSレベルで隔離する。本番バックアップを別媒体へ保管し、復元演習を行う。
- ブラウザ検証：この作業環境ではChromium起動に必要な `libatk-1.0.so.0` がなく、Playwright全体を完了できていません。OS依存ライブラリを導入した環境でPC／モバイルの全シナリオを再実行する。
