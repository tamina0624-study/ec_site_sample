# ローカルのファイル処理・領収書・復元手順

更新日：2026年10月1日。外部サービスへの登録・課金・実決済・メール送信は行いません。Node.js 24と、必要に応じて無料のLibreOffice・Poppler・ClamAVを使用します。

## 無料ツールの準備

PPTXの画像変換にはLibreOffice ImpressとPopplerの `pdftoppm`、ウイルス検査にはClamAVの `clamscan` とウイルス定義が必要です。Debian／Ubuntuでは管理者権限のある端末で次を実行できます。macOS／Windowsでは各ツールを導入し、実行ファイルのフルパスを指定してください。

```sh
sudo apt-get install libreoffice-impress poppler-utils clamav fonts-noto-cjk
npm run tools:check
```

`tools:check` は実行ファイルの起動確認です。ClamAVの定義ファイルの存在・鮮度や、すべてのPPTXの検査完了を保証するものではありません。ClamAV公式の定義をローカルで準備・更新してください。通常はClamAVのfreshclamで更新します。更新にはインターネット接続が必要ですが、アカウント登録は不要です。アプリから自動で外部へ接続して定義を取得することはありません。

| 環境変数 | 内容 |
| --- | --- |
| `LIBREOFFICE_PATH` | LibreOfficeの実行ファイル。既定 `libreoffice` |
| `PDFTOPPM_PATH` | Popplerの実行ファイル。既定 `pdftoppm` |
| `CLAMSCAN_PATH` | ClamAVの実行ファイル。既定 `clamscan` |
| `CLAMAV_DATABASE_DIR` | ローカルのウイルス定義ディレクトリ。未指定なら `SHOP_DATA_DIR/clamav` が存在する場合はそこ、なければClamAV既定の保存先 |
| `SHOP_SCAN_MODE` | `auto`（既定）、`required`、`off` |

実行ファイルの指定は、パスのみです。引数を連結したコマンド文字列は指定できません。指定を変えたらサーバーを再起動してください。

## 画像プレビューとウイルス検査

管理画面で単品商品を編集し、「画像プレビュー生成・ウイルス検査」を実行します。新しいPPTXのアップロードでも同じ処理を行います。まとめて準備する場合はサーバー停止後に次を実行します。

```sh
npm run assets:prepare
```

構造・サイズ・マクロ・埋め込みファイル・外部参照・XML実体を検査してから、ClamAVで検査し、LibreOfficeでPDF化、pdftoppmで最大12ページのPNGを作成します。変換は各コマンド90秒で打ち切り、シェルを介さず実行します。一時プロファイルでマクロを無効化します。日本語の欠字を防ぐため、プレビュー変換時のYu GothicはNoto Sans CJK JPへ置換します。元のPPTXは変更しません。fonts-noto-cjkを導入してください。アプリからのファイル処理は同時に1件です。

画像は `data/previews/SHA-256/ページ番号.png` に保存します。一般公開するのは公開商品のプレビューAPIのみで、DB・PPTX・一時PDFを直接配信しません。セットでは先頭商品の画像を表示します。PPTX全体を取得するには従来の購入権限が必要です。変換画像では全ページの内容が見える場合があるため、実販売で何ページを公開するかは別途決めます。

- `auto`：ClamAVの実行ファイルが見つからない場合は `unavailable` として登録できます。導入済みでも定義不足・処理失敗なら登録を拒否します。
- `required`：ClamAV検査を完了できないアップロードは拒否し、未検査の既存商品・セットは公開／新規購入できません。初期サンプルも先に検査が必要です。
- `off`：検査を明示的に無効化し、`disabled` と記録します。学習用の確認に限って使用してください。
- 問題検出は `infected`。登録を拒否し、既存の同じ版でも購入・公開・取得・プレビューを停止します。購入時の過去版が別のSHA-256なら、その版は別に判定します。
- 画像変換が未導入・失敗した場合は文字抜粋へ戻します。検査が完了したことと画像が生成されたことを区別します。

`assets:prepare` は処理未完了があれば終了コード1を返します。管理画面は各商品の `scanStatus` と画像／文字抜粋を表示します。ウイルス検査は絶対的な安全保証ではなく、定義の準備・更新は運営者の責任です。変換エンジン自体をOSのサンドボックスへ隔離する構成は未実装です。

## 模擬領収書

新しい注文の完了画面・履歴から「模擬領収書を表示・印刷」または「HTMLを保存」を選べます。ブラウザの印刷機能でPDF保存もできます。

購入時の商品・セット名、単品／セットの販売価格、小計、クーポン割引、合計を注文へ保存します。セットは構成商品の単品価格の合計ではなく、実際の模擬セット価格を記載します。税額は割引後の税込合計をすべて仮の10%対象として `floor(合計 / 11)`、税抜は合計との差額です。ゼロ円にも対応します。

同じブラウザの注文だけを表示します。返金後は購入時記録を残し、「全額模擬返金済み」と明示します。リセット後は取得できません。古い注文に購入時データがなければ後付けで領収書を作りません。宛名・住所は収集せず、販売者は学習用表示です。実入金の証明・適格請求書・経費精算には使えません。実販売の税区分・税計算・登録番号・販売者情報は未確定です。

## バックアップの確認と復元演習

```sh
npm run backup
npm run backup:list
npm run backup:check -- backup-実際の名前
npm run restore:drill -- backup-実際の名前
```

自動バックアップの `auto-backup-...` も指定できます。一覧は保存先を探すための機能で、未検証と表示します。検証はDB・ファイルのSHA-256、SQLite整合性、外部キー、商品・購入時ファイルの存在を確認します。復元演習は一時ディレクトリにコピーして再検証し、終了時に削除します。稼働中のDB・パスワード・購入権限を変更しません。完全な業務復旧の確認には、別環境でサーバーを起動し、画面とダウンロードも確認してください。

実際の復元は次の順序です。

1. `backup:list` で対象を選び、`backup:check` と `restore:drill` を実行する。
2. 開発・プレビューサーバーを停止する。
3. `npm run restore -- バックアップ名` を実行する。現在のDBがあれば復元前に手動バックアップを作成する。
4. 必要なら `npm run admin:reset` を実行する。復元時の管理資格情報へ戻るため、MFAの復旧コードやローカルパスワードファイルとの対応を確認する。リセットするとMFA・管理セッションも解除される。
5. 画像キャッシュはバックアップに含めないため、必要に応じて `npm run assets:prepare` で再生成する。キャッシュがなくても文字抜粋と購入時PPTXは利用できる。
6. サーバーを起動し、注文件数、購入時の資料・規約・模擬領収書、取得リンク、管理画面、通知状態を確認する。
7. 不整合があれば停止し、復元前に作られたバックアップを同じ手順で検証・復元する。

バックアップには問い合わせ・管理資格情報・MFA秘密情報も含まれます。別媒体へ安全にコピーし、媒体からの検証・復元演習も行ってください。同じディスクへの自動保存だけではディスク故障に対応できません。運用者が行った復旧確認の日時と結果は、Gitへ秘密情報を書かずに記録してください。

## 検証コマンド

```sh
npm run build
npm run test:server
CHROMIUM_PATH=/usr/bin/chromium npm test
# LibreOffice・pdftoppm・ClamAV導入後のみ
npm run test:tools
```

ブラウザテストは共通の一時DBと同時1件のファイル処理を利用するため、順番に実行します。競合拒否はサーバーテストで別途確認します。

`test:tools` は初期6商品の各4ページを実際に変換し、ClamAVへそのテストだけの無害な検証文字列の定義を読み込ませて、正常・検出・定義不正を確認します。通常運用の公式ウイルス定義や最新の脅威に対する検出率の検証ではありません。
